# Graphics.RenderMeshIndirect: практическое руководство и разбор механики

Учебный, но полностью рабочий пример GPU-driven рендеринга без Entities/ECS — чистый
`UnityEngine.Graphics` + обычный `ComputeShader`. Тысячи инстансов рисуются одним draw call'ом,
а видимость (дистанция, конус обзора камеры, перекрытие другой геометрией) и уровень детализации
считает GPU, а не CPU.

Документация разбита на страницы — слева навигация, справа на каждой странице список её разделов
для быстрого перехода. Читать по порядку не обязательно: если вы уже настроили компонент и просто
ищете, почему что-то не работает — идите сразу в [Диагностику](04-diagnostics.html) или
[Грабли](05-gotchas.html).

## С чего начать

- **Не уверены, что такое draw call, буфер, шейдер или compute shader?** Начните с
  [Основ](00-basics.html) — без этого дальше будет непонятно, а не потому что там что-то сложное.
- **Термины понятны, но конкретно этот компонент видите первый раз?** Начните с
  [Быстрого старта](01-quickstart.html) — как повесить компонент, что настраивать, как включить culling.
- **Хотите понять, ПОЧЕМУ это работает**, а не просто скопировать настройки? Идите в
  [Архитектуру](02-architecture.html) и [GPU-culling](03-culling.html).
- **Что-то пропадает/мигает/не рисуется?** [Диагностика](04-diagnostics.html) — инструменты для
  поиска, какая именно стадия виновата, плюс объяснение битовых масок, которые эти инструменты
  печатают в консоль.
- **Хотите разные уровни детализации по дистанции?** [LOD](06-lod.html) — как это устроено поверх
  той же архитектуры буферов.
- **Собираете справочник по частым ошибкам** — [Грабли и шейдеры](05-gotchas.html).

## Кто за что отвечает

В системе пять слоёв, и **каждый не знает о существовании остальных** — кроме имени буфера,
через который они связаны. Это специально: можно поменять один слой, не трогая остальные (например,
переписать шейдер на Shader Graph, ничего не меняя в C#).

| Слой | Файл | Отвечает за |
|---|---|---|
| C#, оркестратор | `IndirectMeshRenderer.cs` | `MonoBehaviour`: Inspector-поля, генерирует данные инстансов, каждый кадр запускает culling (если включён) и сам draw call. Тонкий - не хранит буферы напрямую, использует два класса ниже |
| C#, данные инстансов | `InstanceBuffer.cs` | Владеет GPU-буфером позиций/масштаба/поворота, минимальный API для их правки (`SetPosition`/`Offset`). Не знает про culling/рендер - переиспользуем отдельно |
| C#, culling + LOD | `GpuIndirectCuller.cs` + `GpuIndirectCullerHelpers.cs` | Диспетчит `IndirectCulling.compute`, владеет буферами выживших/аргументов на каждый LOD-уровень. Тоже не завязан на `IndirectMeshRenderer` |
| Отбраковка (опционально) | `IndirectCulling.compute` | Решает на GPU, какие инстансы попадут в текущий кадр — по дистанции, по конусу обзора камеры (frustum) и по тому, что перекрыто другой геометрией (occlusion). Ничего не рисует сам — только фильтрует |
| Отрисовка | `IndirectCube.shader` или Shader Graph + `IndirectInstancing.hlsl` | Читает финальный буфер (после culling'а или без него) и превращает данные инстанса в вершину на экране |

Если что-то не работает — сначала определите, **в каком из пяти слоёв** проблема, прежде чем
читать код. Это экономит время: подавляющее большинство багов в этой механике — рассинхрон между
C#-стороной и шейдером/compute-шейдером (см. [Грабли](05-gotchas.html)).
