Быстрый старт

Как повесить компонент и получить работающую "поляну" инстансов, потом — как включить GPU-driven culling. Про то, ПОЧЕМУ это так устроено — на других страницах, здесь только практика.

Как настроить с нуля

Это про настройки самого компонента, не про то, как создать GameObject в Unity — это вы уже умеете.

  1. Повесьте IndirectMeshRenderer на любой GameObject.
  2. _mesh / _material — необязательны: без меша возьмётся временный куб, без материала — общий Custom/IndirectCube. Задавайте вручную, если нужен свой меш или Shader Graph-материал (см. Грабли и шейдеры).
  3. _instanceCount, _spread, _minScale/_maxScale, _minYRotation/_maxYRotation — параметры генерации "поляны" инстансов (детали — Как расставляются объекты).
  4. _targetCamera — необязательно, по умолчанию берётся Camera.main. Указывайте явно, если в сцене несколько камер сразу (сплитскрин, миникарта) — иначе поймаете просадку FPS, разобранную в разделе про камеру.
  5. Нажмите Play — увидите "поляну" кубов вокруг позиции объекта.

Как включить GPU-driven culling

  1. Назначьте ассет IndirectCulling.compute в поле _cullingShader.
  2. Включите галочку _useComputeCulling.
  3. _cullRadius — радиус в мировых единицах вокруг _targetCamera, внутри которого инстанс вообще рассматривается как кандидат на отрисовку (грубый предварительный фильтр).

Дальше — три теста подряд (дистанция → frustum → occlusion), каждый со своей галочкой-переключателем:

ПолеПо умолчаниюСмысл
_enableDistanceCulling✅ включеноТест 1 — сфера вокруг камеры, см. Тест 1: дистанция
_enableFrustumCulling✅ включеноТест 2 — конус обзора камеры, см. Тест 2: frustum culling
_enableOcclusionCulling⚠️ выключеноТест 3 — что перекрыто другой геометрией, см. Тест 3: occlusion culling. Выключено по умолчанию осознанно: исторически давал нестабильные ложные отбраковки, включайте только когда реально нужно и готовы проверить результат через диагностику
_invertOcclusionвыключеноДиагностика: буквально переворачивает результат occlusion-теста
_boundsRadiusOverride0 (авто из _mesh.bounds)Радиус ограничивающей сферы ОДНОГО инстанса для frustum-теста. Задайте руками, если авто-значение не соответствует реальному видимому размеру
_boundsExtentsOverride(0,0,0) (авто из _mesh.bounds.extents)Полу-размер по X/Y/Z для 6 сэмпл-точек occlusion-теста. Важно: должен примерно соответствовать реальным пропорциям меша — см. известные ограничения

Оба override-поля читаются каждый кадр, не только при старте — правки в инспекторе во время Play mode применяются сразу, в том числе к реальному GPU-тесту, а не только к диагностическим гизмо.

Настраивать больше нечего для базового включения. Полный разбор всех трёх тестов — GPU-culling. Если что-то отбраковывается неправильно — Диагностика.

Как двигать инстансы

На IndirectMeshRenderer есть два готовых метода под нечастые изменения:

// Один конкретный инстанс - дёшево, для нечастых точечных правок.
renderer.SetInstancePosition(index: 42, worldPosition: new Vector3(10f, 0f, 5f));

// Вся "поляна" разом, когда подвинули сам GameObject - дорого, вызывать редко/по событию.
renderer.RecenterToTransform();

Если вам нужно двигать МНОГО инстансов КАЖДЫЙ кадр (анимация, физика, ветер) — ни один из этих методов не подходит, нужна третья, GPU-side техника, которой в демо-компоненте нет, но которая разобрана полностью — см. Как менять позицию инстансов — общая техника на странице Архитектура.

Как подключить свой шейдер / Shader Graph

Короткая версия (полная — на странице Грабли и шейдеры):

  • Любой шейдер, который сам явно читает _InstanceBuffer по SV_InstanceID/ноде Instance ID, подходит — не важно, написан он руками (IndirectCube.shader) или собран в Shader Graph (IndirectInstancing.hlsl + reflected-нода Apply Instance Transform).
  • Обычный готовый Lit/PBR-материал не подходит, пока в него не встроена эта логика — см. Какие материалы/шейдеры поддерживаются.
