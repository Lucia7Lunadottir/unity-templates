SwarmNav

Навигация на десятки тысяч агентов поверх NavMesh Unity. Пути, высота поверхности, стены и NavMeshLink берутся у NavWorld (Unity.AI.Navigation.LowLevel, Unity 6.6) - тот же NavMesh, который вы запекаете через NavMeshSurface, без отдельного бейка. SwarmNav добавляет то, чего у NavMeshAgent на тысячах агентов нет: всё считается Burst-джобами на воркерах, агентов прореживает LOD по камере, толпа обходит друг друга через spatial hash, а результат либо пишется в Transform одним многопоточным джобом, либо отдаётся массивом/буфером для RenderMeshIndirect.

Если хотите максимально просто, как с NavMeshAgent: запеките NavMeshSurface как обычно, киньте SwarmAgent на GameObject и зовите agent.SetDestination(pos). Больше ничего назначать не нужно. Есть speed, stoppingDistance, remainingDistance, pathStatus, isStopped, ResetPath, Warp - как у NavMeshAgent. Подробнее - 02-swarm-agent.md.

SwarmAgent не имеет своего Update(). Это тонкая обёртка над одним общим SwarmCrowd на сцену. Весь кадр для ВСЕХ агентов идёт Burst-джобами, которые ставит один общий драйвер. Подробнее - 03-swarm-crowd.md.

Если агентов десятки тысяч и они не GameObject (VAT-толпа, RenderMeshIndirect) - берите SwarmNav напрямую: Agents (массив состояний) и AgentsGpu (тот же массив в GraphicsBuffer). Подробнее - 05-advanced.md.

Что внутри

Что Чем делается
Путь до цели NavWorld.BeginFindPath/ContinueFindPath/EndFindPath в Burst-джобе на каждом воркере + funnel (углы кратчайшего пути)
Высота и стены NavWorld.MoveLocation: шаг по поверхности NavMesh возвращает и точку на ней, и упор в границу
Острова и мосты сама сетка NavMesh и NavMeshLink: агент проходит по связи прыжком вход -> выход
Близкая цель NavWorld.Raycast: если до цели нет стен, идёт напрямую, без расчёта пути
Погоня цель-Transform читается один раз на группу, путь агента пересчитывается, когда цель заметно сместилась
Обход соседей разведение на GPU (ComputeShader, uniform grid) для всех агентов; без compute - spatial hash на CPU
Толпа у одной цели правило прибытия: коснулся прибывшего из своей группы - встал, диск растёт наружу
LOD тиры Near/Mid/Far по расстоянию до камеры: дальние шагают раз в N кадров
Запись в Transform IJobParallelForTransform по TransformAccessArray из TransformHandle

Если коротко

  • NavMesh запекается как обычно; бейка своей сетки нет. Тип агента и маска областей - в SwarmNavSettings.
  • Один SwarmNav и один SwarmCrowd на сцену, драйвер создаётся сам. Tick() для SwarmAgent вызывать не нужно.
  • Любой метод SwarmNav/SwarmAgent, который читает или пишет данные агента, сам дожидается джобов кадра.
  • Фокус LOD - объект с тегом MainCamera (LodFocusTag). Без него все агенты считаются Near (полное качество).
  • Путь агента, назначенный в этом кадре, начинает выполняться со следующего: пути считаются в фоне после шага.
  • Замеры в Editor (режим энергосбережения процессора, 20 000 агентов): ожидание навигации 1,6-5 мс на кадр, с разведением и LOD. Потолок для двигающихся GameObject (~17-20 FPS на 21 000) задаёт сам Unity, не навигация; для десятков тысяч нужен RenderMeshIndirect. Подробности и оговорки про Editor/Profiler - 07-performance.md.
  • Domain Reload в проекте отключён: статики переживают Stop/Play (08-behaviour-and-lod.md, раздел 5).
