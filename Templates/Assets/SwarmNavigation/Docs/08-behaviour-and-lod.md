# Патруль, погоня, LOD

## 1. Два вида цели

| | Личная точка | Погоня за `Transform` |
|---|---|---|
| Вызов | `agent.SetDestination(Vector3)` | `agent.SetDestination(TransformHandle)` |
| Кто делит цель | никто, у агента своя точка | все агенты с одним `Transform` читают его позицию один раз за кадр |
| Путь | свой, считается один раз | свой, пересчитывается, когда цель смещается |
| Лимит разных целей | нет | до 256 разных целей-`Transform` одновременно (`MaxGroups`) |
| После прибытия | `hasDestination = false` | `hasDestination` остаётся `true`: агент следует за целью дальше |

Раньше был лимит 8 разных общих целей из-за GPU-слотов flow field; теперь пути у каждого агента свои, и лимит 256 - только
на число отслеживаемых движущихся целей, а не на агентов.

В `SwarmNav` напрямую то же самое: `SetDestination(handle, pos)` и `SetSharedGoal(handle, pos, groupKey)` +
`UpdateSharedGoalPosition(groupKey, pos)`.

### 1.1. Как пересчитывается путь при погоне

Путь агента пересчитывается, если одновременно:

1. цель сместилась больше чем на `max(ChaseRepathDistance, ChaseRepathFraction * расстояние до цели)` с момента расчёта пути;
2. с прошлого расчёта прошло `RepathCooldown` (Near 0,25 с, Mid 1 с, Far 3 с);
3. агент не идёт напрямую (`DirectMoveRange`).

Дальний агент идёт к устаревшей точке дольше, ближний обновляется чаще, а у цели (≤ 30 м и без стен) путь не нужен.
За кадр считается не больше `PathRequestsPerFrame` путей: если преследователей много, часть ждёт очереди. Пример замера:
20 000 агентов гонятся за одним агентом на карте ~1 км - за ~45 с медиана расстояния до цели падает с 444 до 321 м, число
агентов ближе 30 м растёт с 95 до 1454 (они же и есть те, кто идёт напрямую). Такая погоня на весь мир дальше дойдёт
к цели постепенно; если нужна быстрее - поднимите `PathRequestsPerFrame` (стоит воркеров, не главного потока).

## 2. Патруль -> погоня -> атака

`SwarmPatrolChaseExample.cs`: один менеджер на всю толпу, один `Update()`, по массиву `SwarmAgent`.

- **Патруль:** `SetDestination(случайная точка)`; новая точка, когда `!hasDestination` или `remainingDistance <=
  stoppingDistance + 0,5`.
- **Погоня:** игрок ближе `sightRange` -> `SetDestination(player.transformHandle)`. Потерял игрока на `1,5 * sightRange` ->
  патруль (гистерезис против дрожания границы).
- **Атака:** ближе `attackRange` -> `isStopped = true`, событие `Attacked` по `attackCooldown`; вышел за `1,2 * attackRange` ->
  `isStopped = false` и снова погоня. `stoppingDistance = 0,9 * attackRange`: агент встанет на дистанции удара сам.

Менеджер с одним циклом по массиву дешевле `Update()` на каждом агенте. Решения («что делать») можно принимать не каждый
кадр (например, по 1/10 агентов за кадр): навигацию это не затрагивает.

## 3. LOD по расстоянию до камеры

Фокус LOD - объект с тегом `LodFocusTag` (по умолчанию `MainCamera`); рантайм находит его сам раз в 60 кадров,
пока не нашёл, и обновляет его позицию каждый кадр. Без фокуса все живые агенты считаются **Near** (полное качество).

| Поле (`SwarmNavSettings.Lod`) | Смысл |
|---|---|
| `NearRadius` | Внутри - Near: шаг **каждый кадр**, разведение. По умолчанию 60 м. |
| `MidRadius` | До него - Mid: шаг раз в `MidUpdateEveryNFrames` кадров, разведение. По умолчанию 150 м. |
| `MidUpdateEveryNFrames` | По умолчанию 2. |
| `FarUpdateEveryNFrames` | Дальше `MidRadius` - Far: шаг раз в N кадров, **без разведения** (`SeparateFarAgents`). По умолчанию 4. |
| `LodSmoothing` | Сглаживание Mid/Far в кадре камеры (`03-swarm-crowd.md`, раздел 5). |

`ShowLodGizmos` рисует в Scene View зелёное кольцо `NearRadius` и жёлтое `MidRadius` вокруг фокуса.

### 3.1. Как подобрать расстояния

1. Включите гизмо и посмотрите, где граница видимых деталей (примерно по размеру агента на экране).
2. `NearRadius` - там, где «шаг раз в 2 кадра» становится заметен: обычно 40-80 м для человека.
3. `MidRadius` - где разведение и частота шага ещё важны, но агент мал: 120-200 м.
4. `FarUpdateEveryNFrames` - чем больше, тем дешевле и тем заметнее рывки дальних; для рывков есть `LodSmoothing`.

### 3.2. Что LOD ускоряет, а что нет

- Ускоряет: `Steer` и `Move` (шагают раз в N кадров), хэш и разведение (Far в нём нет), запись `Transform` (у дальних вне
  кадра - только на шаге).
- Не ускоряет: расчёт путей (они считаются по заявке, не по тиру; для дальних реже только пересчёт при погоне),
  регистрацию и `Collect` (он просматривает агентов подряд, пока не наберёт бюджет заявок).

## 4. NavMesh, острова, связи

- Агенты ходят по **любой** части NavMesh, запечённой `NavMeshSurface`: земля, Terrain-тайлы, плавающие острова.
- Разорванные части соединяются `NavMeshLink`; агент проходит связь прыжком по прямой вход -> выход. Дуги/анимации прыжка
  нет, скорость - `speed * LinkSpeedMultiplier`.
- Цель в отрезанной части без связи -> `pathStatus == Partial`: агент доходит до ближайшей достижимой точки.
- Высота - высота поверхности NavMesh в точке агента. Слои друг над другом не путаются: агент привязан к полигону,
  на котором стоит, и `MoveLocation` не перепрыгивает на другой слой.
- Объём запекания, качество, `Agent Type`, области (`AreaMask`) - настройки вашего `NavMeshSurface`/`SwarmNavSettings`.

### 4.1. baseOffset

`SwarmAgent.baseOffset` - смещение Y модели над поверхностью NavMesh, как у `NavMeshAgent`. Для куба с пивотом в центре -
половина высоты. Если модель висит в воздухе или утонула - начните с него.

## 5. Domain Reload отключён: статики переживают Stop/Play

В проекте отключён Domain Reload (Enter Play Mode Options), поэтому статические поля не сбрасываются между запусками.
`SwarmNavRuntime` сам сбрасывает свои статики (общий `SwarmCrowd`, драйвер, фокус LOD) на старте каждого Play через
`[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]`. Если вы добавляете свои статические поля, сбрасывайте их так же.
